# Техническое задание  
## Симуляция банка под нагрузкой

### Цель
Закрепить практическую работу с:
- goroutine
- sync.Mutex
- sync.WaitGroup

Без использования каналов и sync/atomic.

---

## 1. Описание задачи

Необходимо реализовать простую симуляцию банка, в которой несколько горутин параллельно выполняют переводы между счетами.

Задача направлена на отработку:
- корректной блокировки общих ресурсов
- ожидания завершения горутин
- предотвращения гонок данных и дедлоков

---

## 2. Модель данных

### Счёт

```go
type Account struct {
    ID      int
    Balance int
    mu      sync.Mutex
}
```

### Банк

```go
type Bank struct {
    Accounts []*Account
}
```

---

## 3. Операция перевода

Реализовать метод:

```go
func (b *Bank) Transfer(fromID, toID int, amount int) bool
```

### Правила:
- fromID и toID не могут быть равны
- Если на счёте from недостаточно средств — перевод не выполняется
- При успешном переводе:
  - баланс from уменьшается на amount
  - баланс to увеличивается на amount
- Метод должен быть безопасен при параллельных вызовах
- Дедлоки недопустимы

Метод возвращает:
- true — если перевод выполнен
- false — если перевод отклонён

---

## 4. Нагрузка

В функции main:

- Создать N = 100 счетов
- Начальный баланс каждого счёта: 1000
- Запустить M = 10 воркеров (goroutine)
- Каждый воркер выполняет K = 10_000 переводов

### Поведение воркера:
- Случайным образом выбирает:
  - fromID
  - toID
  - amount (от 1 до 100)
- Вызывает Transfer
- Ведёт локальный счётчик:
  - успешных переводов
  - неуспешных переводов

---

## 5. Синхронизация

- Для ожидания завершения всех воркеров использовать sync.WaitGroup
- Для защиты балансов использовать sync.Mutex
- Использование каналов запрещено
- Использование sync/atomic запрещено

---

## 6. Проверки после выполнения

После завершения всех воркеров необходимо:

1. Посчитать общую сумму денег во всех счетах
2. Убедиться, что она равна стартовой сумме
3. Убедиться, что ни один баланс не стал отрицательным

---

## 7. Вывод результата

В конце работы программы вывести:

- стартовую сумму денег
- финальную сумму денег
- количество успешных переводов
- количество отклонённых переводов
- минимальный и максимальный баланс среди счетов

---

## 8. Дополнительные требования

- Программа не должна зависать
- Программа должна корректно завершаться
- Решение должно стабильно работать под нагрузкой
- Рекомендуется проверить работу с помощью:

```bash
go run -race main.go
```

---

## 9. Критерий выполнения

Задача считается выполненной, если:
- программа завершается без зависаний
- итоговая сумма денег совпадает со стартовой
- race detector не сообщает о проблемах
